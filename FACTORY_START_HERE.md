# AI Polygon Problem Factory — start here

This is a fork of [7oSkaaa/polygon-problems-generator](https://github.com/7oSkaaa/polygon-problems-generator). The original idea-to-problem pipeline remains available. **Factory** is an incremental extension for importing an existing problem, optionally using a user-provided algorithm or accepted solution, generating strong tests, and synchronizing to Polygon.

## Current reality (2026-10-15)

- **Implemented in this stacked branch:** governance docs, structural preflight, API timeout/error handling, mock-verified package polling, read-only sync planning, and offline V1 problem-spec schema/adapter.
- **Inherited upstream, not yet revalidated on a real account:** the Claude-oriented agent roles, local `verify.sh`, and `polyup` Polygon upload flow.
- **Not implemented yet:** text/PDF/image ingestion (ING-002), algorithm discovery, strong-test engine, repair orchestration, live Polygon integration and unattended publishing.

## Start an agent session

1. Read [docs/factory/HANDOFF.md](docs/factory/HANDOFF.md) and [docs/factory/TASKS.md](docs/factory/TASKS.md) first.
2. Read [docs/factory/AGENT_RULES.md](docs/factory/AGENT_RULES.md) and [docs/factory/ARCHITECTURE.md](docs/factory/ARCHITECTURE.md).
3. Choose **exactly one** ready task, inspect affected upstream files, and implement + test it.
4. Update the task board and handoff with evidence and remaining blockers in the same PR.
5. Do not claim Polygon success without a completed server-side verified package.

## Local first checks

~~~bash
python3 -m unittest discover -s tests -v
python3 -m polyup preflight <existing-problem-name-or-path>
./verify.sh problems/<name>
~~~

The second command is read-only and does not need Polygon secrets. Preflight is a **structural** check, not a proof of correct solutions. The last command requires the original repository's C++/Java/testlib dependencies.

Read [docs/factory/PROMPTS.md](docs/factory/PROMPTS.md) for paste-ready Codex/Antigravity prompts and [docs/factory/ROADMAP.md](docs/factory/ROADMAP.md) for milestones.

**Keep `.claude/shared.md` as the upstream role source of truth.** The root `AGENTS.md` is auto-generated by `sync-ai-configs.py`; do not introduce conflicting rules there.

## Safe Polygon sync (API-003)

Read-only plan (default; remote reads use credentials for existing problems):

~~~bash
python3 -m polyup <problem-name>
~~~

After independently reviewing the plan, an approved new problem may be created by `python3 -m polyup <problem-name> --apply`. An existing Polygon problem requires `--apply --allow-overwrite`, optionally with `--expected-revision <revision>`. **Do not use --apply for a real Polygon problem before an approved integration test.** Metadata comparisons cannot prove remote source equality; this is a safety gate, not full content diff.

## Offline problem specification (ING-001)

See [V1 spec contract](docs/factory/PROBLEM_SPEC_V1.md). With optional user idea or solution:

~~~bash
python3 -m pip install -r requirements-factory.txt
python3 -m factory spec from-local problems/<name> --output problems/<name>/spec.json
python3 -m factory spec validate problems/<name>/spec.json --ready
~~~

The converter creates a DRAFT with explicit unknown constraints/case/output semantics; readiness normally fails until reviewed. No Polygon writes occur.
